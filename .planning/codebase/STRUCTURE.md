# Codebase Structure

**Analysis Date:** 2026-07-27

## Directory Layout

```text
logbook/
├── logbook-pwa/                 # React/Vite static PWA
│   ├── src/
│   │   ├── components/          # Mounted UI, recording, playback, admin curation
│   │   ├── lib/                 # Protocol, trust, auth, storage, and state helpers
│   │   └── types/               # Shared Nostr/domain types
│   ├── scripts/                 # Puppeteer responsive QA runners
│   ├── public/                  # Static PWA assets copied into the build
│   ├── dist/                    # Generated production bundle
│   └── package.json             # Client scripts and dependencies
├── scripts/                     # Trusted watcher/stitch/release worker
│   ├── test/                    # Node test suites and native integration test
│   └── package.json             # Worker scripts and dependencies
├── deploy/
│   └── systemd/                 # Hardened worker unit and protected env template
├── docs/                        # Operations runbook and engineering backlog
├── research/                    # Historical, non-authoritative research
├── .planning/                   # GSD project, roadmap, state, and codebase map
├── .hermes/                     # Local plans; intentionally untracked
├── AGENTS.md                    # Automated-contributor working contract
├── README.md                    # Product status and development entry point
├── SPEC.md                      # Canonical wire and trust specification
└── PLAN.md                      # Current architecture and remaining roadmap
```

## Directory Purposes

**`logbook-pwa/src/components/`:**
- Purpose: user-visible production surfaces.
- Contains: PascalCase React components and colocated CSS/tests.
- Key files: `IssueTimeline.tsx`, `InlineRecorder.tsx`, `VoiceBubble.tsx`, `ReleaseChecklist.tsx`, `WhitelistPanel.tsx`.
- Add UI only after tracing the mounted path from `App.tsx` or `IssueTimeline.tsx`; an unused component does not satisfy a requirement.

**`logbook-pwa/src/lib/`:**
- Purpose: browser-side domain logic and external boundaries.
- Contains: auth/session, relay, Compass issue, whitelist, segment, manifest, draft, upload, playback, and request-generation helpers.
- Key files: `auth.ts`, `segment.ts`, `manifest.ts`, `blossom.ts`, `drafts.ts`, `latest-request.ts`, `signer-identity.ts`.
- Tests are usually collocated as `*.test.ts`.

**`logbook-pwa/src/types/`:**
- Purpose: cross-module Nostr and Logbook TypeScript shapes.
- Key file: `nostr.ts`.
- `publishedRss` includes the metadata needed to reconstruct a durable origin feed.

**`logbook-pwa/scripts/`:**
- Purpose: real Chromium layout checks outside Vitest.
- Key files: `public-shell-qa.mjs`, `qa-episode.mjs`, `playback-qa.mjs`, and `resume-cache-qa.mjs`.
- These start/load the production app and check responsive overflow/visibility at supported widths.

**`logbook-pwa/public/` and `dist/`:**
- `public/` contains static assets; generated NIP-05 output is produced by the build rather than hand-maintained here.
- `dist/` is generated by `npm run build`; release proof compares its exact hashes against one public gateway.
- Do not hand-edit `dist/` as source.

**`scripts/`:**
- Purpose: trusted native worker and controlled operational utilities.
- Core flow: `watch-compass.ts` → `stitch.ts` → `publish-rss.ts`.
- Trust/state helpers: `watch-state.ts`, `watch-runner.ts`, `segment-security.ts`, `stitch-download.ts`, `stitch-state.ts`, `release-state.ts`, `rss-state.ts`, `static-sync.ts`.
- Signer boundary: `amber-signer.ts`.
- Manual utilities: `transcribe-missing.ts`, `seed-whitelist.mts`, `generate-intros.ts`.

**`scripts/test/`:**
- Purpose: pure and integration tests for the trusted worker.
- Contains: `*.test.ts` node:test files and `stitch-media.integration.test.ts` for real ffmpeg/ffprobe execution.
- Tests should inject side effects through dependency objects where possible, as in `watch-runner.test.ts` and `release-state.test.ts`.

**`deploy/`:**
- Purpose: production worker installation boundary.
- Key files: `deploy/systemd/logbook-worker.service`, `deploy/systemd/logbook.env.example`, `deploy/README.md`.
- The committed env file is a template. The deployed `/etc/logbook/logbook.env`
  includes signer-session credentials and must be root-owned, mode `0600`, and never committed.

**`docs/`:**
- Purpose: executable operations evidence and maintained engineering context.
- `operations-and-testing.md` owns pre-merge/release commands, signer handling, worker recovery, static-host acknowledgement, and nsite proof.

**`.planning/`:**
- Purpose: GSD living project context.
- Contains: `PROJECT.md`, `REQUIREMENTS.md`, `ROADMAP.md`, `STATE.md`, `config.json`, and this `codebase/` map.
- Historical implementation claims must remain separated from operational evidence.

## Key File Locations

**Entry Points:**
- `logbook-pwa/src/main.tsx` — browser mount.
- `logbook-pwa/src/App.tsx` — production navigation/auth/access orchestration.
- `scripts/watch-compass.ts` — long-running worker entry.
- `scripts/stitch.ts` — exact-cut media command.
- `scripts/publish-rss.ts` — release command.

**Configuration:**
- `logbook-pwa/src/config.ts` — client pubkeys, kinds, relays, Blossom servers, recording constraints.
- `scripts/config.ts` — worker equivalents and filesystem/public URLs.
- `logbook-pwa/vite.config.ts` — relative nsite build and PWA cache policy.
- `deploy/systemd/logbook.env.example` — public worker environment names.

**Core Logic:**
- `logbook-pwa/src/lib/segment.ts` — trusted segment parsing/fetch.
- `logbook-pwa/src/lib/manifest.ts` — manifest read/write validation.
- `logbook-pwa/src/components/IssueTimeline.tsx` — live record/publish/read path.
- `logbook-pwa/src/components/AdminPanel.tsx` — mounted curation path.
- `scripts/stitch-download.ts` and `scripts/stitch-media.ts` — trusted media boundary.
- `scripts/release-state.ts` — idempotent stage ordering.

**Testing:**
- `logbook-pwa/src/**/*.test.ts(x)` — collocated Vitest tests.
- `logbook-pwa/scripts/*.mjs` — browser layout checks.
- `scripts/test/*.test.ts` — worker node:test suites.

**Documentation:**
- `AGENTS.md`, `README.md`, `SPEC.md`, `PLAN.md`, `docs/operations-and-testing.md`.
- `.hermes-handoff.md` records the current release handoff but is not a protocol source.

## Naming Conventions

**Files:**
- PascalCase `.tsx` for React components (`IssueTimeline.tsx`).
- kebab-case `.ts` for domain helpers (`manifest-revision.ts`, `signer-timeout.ts`).
- `*.test.ts` / `*.test.tsx` collocated in the PWA; worker tests live in `scripts/test/`.
- UPPERCASE Markdown names for canonical root contracts; lowercase kebab-case for topical docs.

**Directories:**
- Lowercase or kebab-case collection names (`components`, `lib`, `logbook-pwa`).
- Separate runtime roots instead of a shared package workspace.

**Special Patterns:**
- No barrel files; import concrete modules directly.
- Addressable-event helpers include `manifest`, `whitelist`, or `revision` in names.
- Worker state helpers separate pure selection/state machines from CLI side effects.

## Where to Add New Code

**New PWA capability:**
- UI: `logbook-pwa/src/components/`.
- Trust/state logic: `logbook-pwa/src/lib/`.
- Shared wire shape: `logbook-pwa/src/types/nostr.ts` plus `SPEC.md` and worker consumers.
- Tests: collocated beside the changed module and browser QA when the mounted surface changes.

**New trusted-worker stage:**
- Pure state/validation helper: `scripts/<stage>-state.ts` or a focused module.
- CLI orchestration: `scripts/publish-rss.ts` or a new explicit command.
- Tests: `scripts/test/<stage>.test.ts`; use real native integration only where byte/media behavior matters.
- Operations: update `docs/operations-and-testing.md` and deployment artifacts.

**New protocol field/event:**
- Update `SPEC.md`, both producer and consumer types/parsers, signature/trust checks, and cross-surface tests in the same change.

**New deployment integration:**
- Implementation under `scripts/` with digest read-back.
- Public config in `deploy/systemd/logbook.env.example`; secrets remain outside the repository.
- Installation/recovery steps in `deploy/README.md` and `docs/operations-and-testing.md`.

## Special Directories

**`logbook-pwa/dist/`:**
- Purpose: generated production assets.
- Source: `npm run build`.
- Committed: present in the worktree; treat as build output and verify exact bytes before release.

**`logbook-pwa/node_modules/` and `scripts/node_modules/`:**
- Purpose: installed dependencies.
- Source: npm lockfiles.
- Committed: no; never include in mapping or release staging.

**`.hermes/`:**
- Purpose: local Hermes plan artifacts.
- Source: prior local planning sessions.
- Committed: currently untracked; do not stage blindly.

**`research/`:**
- Purpose: historical option analysis.
- Source: earlier discovery work.
- Committed: yes, but explicitly non-authoritative when it conflicts with current code/spec.
